Definition of Done (DoD) визначає єдиний обов'язковий стандарт якості для визнання історії завершеною у спринті. На відміну від критеріїв приймання (Acceptance Criteria), які є унікальними для кожної функціональної вимоги, DoD є спільним регламентом якості інженерного процесу для всього беклогу.

## Умови, за яких історія вважається завершеною

- **Лінтер та статичний аналіз**: Код успішно проходить автоматичну перевірку лінтером (`flutter analyze` для клієнта, `flake8` для сервісів імпорту) без критичних зауважень та помилок компіляції.
- **Unit-тести**: Написані та успішно пройдені модульні тести для бізнес-логіки обробки розкладу та сервісу кешування; загальний рівень проходження тестів становить 100%.
- **Критерії приймання**: Усі бінарні критерії приймання (Acceptance Criteria), описані в історії беклогу за шаблоном Given/When/Then, перевірені та підтверджені на тестовому середовищі.
- **Тестування QA**: Історія верифікована тестувальником на фізичному пристрої або емуляторі (Android та iOS) відповідно до чек-листа; критичні дефекти відсутні.
- **Збірка та розгортання**: Код влито в основну гілку репозиторію через Pull Request з успішною автоматичною збіркою в CI/CD пайплайні.
- **Валідатор курсу**: Документація та табличні файли відповідають спеціфікації та проходять перевірку `tools/validate.py` без помилок рівня `error`.

## Чого DoD свідомо не вимагає

- **100% покриття коду тестами**: Ми свідомо не встановлюємо штучний поріг кодового покриття (code coverage) у 80–100%, оскільки в умовах жорсткого 10-тижневого дедлайну розробки MVP це призвело б до формального написання неефективних тестів замість стабілізації критичних інтеграцій.
- **Автоматизоване навантажувальне тестування для кожної історії**: Навантажувальне тестування черги пушів проводиться одноразово перед релізом, а не під час закриття кожної окремої користувацької історії.
